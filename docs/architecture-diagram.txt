Flows
-----
  (a) Operator -> both VMs via SSM Session Manager (no keypair, no inbound).
  (b) Node -> Docker Hub image pull, out through NAT -> IGW.
  (c) Linux VM kubectl -> EKS private API endpoint (in-VPC only).
  (d) Linux VM pulls staged assets from the transfer bucket on first boot
      into /opt/cortexlab (non-fatal if nothing staged yet).
  (e) VMs exploit the app by hitting any node's InternalIP on a NodePort.
  (f) Compromised pod calls back to a VM (reverse shell / JNDI listener).
  (g) App -> Cortex XSIAM log shipping via NAT -> IGW (not wired yet).
  (h) Multi-region CloudTrail records all account management + S3/Lambda data
      events to the cloudtrail bucket (log-file validation on).


Security groups (bidirectional)
-------------------------------
  VM SGs      -> cluster SG   : all traffic  (kubectl + exploit traffic)
  cluster SG  -> VM SGs       : all traffic  (callbacks: reverse shell / JNDI)
  VMs                          : no inbound; reached only via SSM


Cluster access
--------------
  Auth mode API_AND_CONFIG_MAP. Each VM instance role is an EKS access entry
  bound to cluster-admin, so kubectl works with no extra credentials.
